# PrivacyGate v2 implementation contract

Approved 2026-10-26. This document supersedes the v1 EVM, wallet identity,
MQTT, deployment, schema-migration and tooling requirements in older documents.
Old `/v1` code is historical, not part of the required runtime. No legacy data
is migrated or deleted. Implementation status belongs in dated results.

## Runtime and trust

Python 3.12, SQLite, FastAPI, Node 24+/npm and PowerShell; no external services.
Frontend versions are pinned to Next 16.4.3 and React 19.3.1 after the inherited
Next 14 dependency audit exposed high/critical advisories. ESLint 10 flat config
replaces next lint. See dated results for the executed compatibility/audit gates.
`privacygate_v2` is a sibling package under apps/gateway/src. Gateway 8000,
validator 8010, web 3000, all loopback. Runtime root `var/v2` is ignored.
Owner transaction signing keys are held by the trusted gateway. Reader X25519
secrets remain browser-memory-only with explicit backup. Single validator is
centralized; no mining or consensus claims. Crypto uses maintained libraries.
Run exactly one gateway worker: signer/device locks serialize submissions in this
process. Multi-worker deployment is outside this local MVP. Simulator signing-key
files are encrypted under the protected raw-data key. The validator key and
gateway signing keys live in the ACL-protected runtime config, never Git.

## Shared encoding and persistence

Canonical JSON: sorted keys, compact UTF-8, ensure_ascii=False, allow_nan=False.
IDs are canonical UUID strings except resource_id = lowercase 0x + 64 hex.
Times: Unix integer seconds in transactions/sessions, ISO UTC milliseconds in
readings/insights. Signature encoding is standard base64. SHA256 hex digests.
Each DB enables foreign keys, WAL and synchronous=FULL, per-operation connections,
explicit transactions. Schema version 2; reject unknown DB versions. Ledger DB
is authoritative; gateway metadata is reconstructable with durable outbox.

## Blockchain module interface (ledger.py and ledger_client.py)

`Ledger(db_path, validator_private_key_b64, identities: dict[account_id, pub_b64],
chain_id='privacygate-local-v2')`. Provisioned identities are immutable/pinned.
`submit(transaction: dict) -> receipt`; `state(resource_id, recipient_id,
challenge: str) -> signed_observation`; `receipt(transaction_id) -> dict | None`;
`verify() -> dict` replays history and verifies derived state. Public config
exposes genesis_hash, chain_id, validator_public_key_b64, identities.
`sign_transaction(private_b64, chain_id, signer_id, nonce, operation, payload,
transaction_id=None, issued_at=None) -> dict`.
Transactions exactly `{schema_version:2,chain_id,transaction_id,signer_id,nonce,
issued_at,operation,payload,signature_b64}`. Signature covers all except signature.
Operations: REGISTER_RESOURCE `{resource_id}`; GRANT `{resource_id,recipient_id,
policy_digest,expires_at,scope:'READ_INSIGHT'}`; REVOKE `{resource_id,recipient_id}`.
Per-signer nonce starts at 1 and advances by 1. Fresh new tx within +/-30 seconds;
exact previously committed retry returns receipt before freshness/nonce checks.
Owner immutable; reader must be provisioned, not owner. No private data on-chain.
Block exactly `{height,previous_hash,committed_at,transaction,block_hash,
validator_signature_b64}`; block_hash=SHA256(canonical block without last two).
Receipt `{transaction_id,block_height,block_hash,operation,resource_id,version}`.
Observation signed body `{chain_id,genesis_hash,challenge,observed_at,head_height,
head_hash,resource_id,owner_id,recipient_id,grant}` plus signature_b64. Grant null
or `{recipient_id,policy_digest,expires_at,scope,active,version}`. Revoke increments
version; regrant increments again. Commit block/index/nonce/state in one tx.
Only successful durable commit is confirmed. Verify history on startup, reject
corruption; persist known head in gateway to detect rollback below known height.
Valid-prefix truncation without external checkpoint and compromised-key rewrite
remain documented limits. Clock regression disables authorization until caught up.
Absent resource observations are signed with owner_id:null and grant:null. They
never authorize disclosure; they allow safe recovery of an uncommitted first
registration without trusting an unsigned 404.

Validator HTTP: POST /transactions body tx; GET /receipts/{id}; GET /config;
POST /state `{resource_id,recipient_id,challenge}`; GET /health. Bind loopback.
`LedgerClient(url, config, checkpoint_path=None)` implements `submit`, `receipt`,
`state(resource_id, recipient_id)` (generates/verifies challenge, signature,
identity, observed_at +/-5s, head monotonicity), and `next_nonce(signer_id)`.
GET /nonces/{signer_id} returns next nonce; gateway serializes per-signer submission.
Failures use LedgerError(code,message), client availability errors fail closed.

## Gateway /v2 API

Every body forbids extras, pagination limit 1..100, opaque stable cursors.
Errors `{error:{code,message,request_id}}`, no secrets or untrusted payloads.
Cookie pg_v2_session HttpOnly SameSite=Strict, 30min, Secure outside loopback.
POST requires exact Origin http://127.0.0.1:3000 (localhost equivalent configured),
plus X-CSRF-Token for authenticated mutations. Login checks Origin and throttles.
Passwords use scrypt/Argon2 maintained implementation; session token hashes at rest.
GET /me returns stable session CSRF token across tabs/reload; never store bearer
tokens or reader private keys in browser storage. Logout deletes server session.
Owner device/grant/revoke mutations accept X-Operation-ID (canonical UUID), also
the signed transaction ID. Persist body fingerprint with operation before work;
same owner+ID+body retries recover the original result, different body is 409.
Client retains ID across uncertain responses and checks /operations/{ID} before
retry. CORS allows this explicit header. Server-generated IDs support CLI callers.
If an uncommitted transaction is over 35 seconds old, a fresh signed observation
and unchanged next nonce can prove its original submission window has closed.
Retain its exact signed bytes but mark the operation terminal FAILED with
OPERATION_EXPIRED; never silently resign it. Reconciliation skips failed rows.
The UI retains form input and allows an explicit new operation after explaining
that the old operation did not commit. Committed retries recover before expiry.

- POST /auth/login `{username,password}` -> `{account_id,username,role,expires_at,csrf_token}`.
- GET /me -> same; POST /auth/logout `{}` -> `{ok:true}`.
- GET /accounts -> owner-only `{items:[{account_id,username,role}]}` for demo invitations.
- GET /devices -> `{items:[{resource_id,device_id,name,ed25519_public_key_b64,last_sequence}]}` owner only.
- POST /devices `{name}` -> same device + `receipt`; generates simulator signing key
  locally, registers random resource on chain, pins device public key persistently.
- GET /resources/{resource_id}/telemetry?limit&cursor -> `{items:[{device_id,sequence,
  issued_at,temp_c,vibration_mm_s,rpm}],next_cursor}` owner only; never reader.
- POST /simulator `{resource_id,mode,count}` mode normal|anomaly|tampered|replayed|
  stale|malformed|wrong-device, count 1..20 -> `{accepted,rejected,deliveries}`.
  Owner-only control of local bounded simulation; same signed ingestion validator,
  no public packet-upload bypass. Chain outage must not stop ingest.
- POST /keys `{x25519_public_key_b64,replace:false}` -> `{key_id,key_version,
  x25519_public_key_b64}`. Same-key registration idempotent, different key requires
  replace=true and invalidates old queues. GET /keys -> own enrollment or null.
- POST /policies `{resource_id,recipient_id,expires_at}` -> `{policy_id,policy_digest,
  resource_id,recipient_id,expires_at,status,version,receipt}`. Fixed allowlist only.
  Persist immutable local draft/outbox before signed GRANT submission.
- GET /policies?resource_id -> `{items:[policy]}` owner only, reconcile current chain.
- POST /policies/{policy_id}/revoke `{}` -> policy + receipt. Idempotent retries.
- GET /operations/{transaction_id} -> own pending/committed receipt, no duplicate submission.
- GET /insights?resource_id&limit&cursor -> `{items:[EnvelopeV2],next_cursor}` reader.
- GET /audit?resource_id -> owner-only `{items:[receipt]}`.
- GET /health -> `{status:'ok'}`; GET /ready -> `{gateway,database,chain}`.

Every dispatch/read validates fresh ledger identity/head, resource, reader,
active scope, current UTC expiry, exact local policy digest and grant version.
Key version additionally matches. Missed invalidation cannot resurrect old queues.
Already-authorized in-flight responses cannot be recalled; linearization at fresh
state observation. Persist ciphertext only. Raw payload AES256GCM before SQLite
write with fresh nonce and resource/device/sequence AAD, sequence+record atomic.
Keep raw 7 days, deliveries 24h, remove expired sessions; execute cleanup on use/start.

## EnvelopeV2

Exactly `{schema_version:2,delivery_id,resource_id,recipient_id,policy_version,
key_version,key_epoch,ephemeral_public_key_b64,nonce_b64,aad_b64,ciphertext_b64}`.
AAD canonical JSON exactly `{schema_version:2,delivery_id,event_id,resource_id,
recipient_id,policy_version,key_version,key_epoch}`. HKDF info UTF8
`privacygate-envelope-v2|` + canonical JSON `{event_id,key_epoch,key_version,
policy_version,recipient_id,resource_id}`. HKDF-SHA256 length32 salt32 zeros;
fresh ephemeral X25519, nonce12 AES256GCM. Plaintext exactly event_id,event_type
MACHINE_ANOMALY,severity LOW|MEDIUM|HIGH,observed_at,model_version. Client rejects
unknown fields, canonical/context mismatch, wrong account/resource and invalid tags.
key_epoch equals the monotonic grant version; recipient-key rotation advances the
independent key_version. Both are enforced at retrieval, preventing old envelopes
from returning after revoke/regrant or rotation.
Backup JSON `{schema_version:2,account_id,public_key_b64,private_key_b64}` local
download/import only; public key must derive from private and match account.
